## Code & Structure Conventions
- **Credit Header:** Every QML, JavaScript, and configuration source file must include the header:
  `// © Mayanktaker Computers & Web Development | https://mayanktaker.com`
- **Default Endpoint:** OpenCode Go usage data comes from the OpenCode Console JSON API. **Primary (verified live):** `GET https://opencode.ai/console/api/go/status` — the workspace/org id is REQUIRED in the `x-org-id` request header (the path carries no org; without that header the server returns HTTP 400 `{"_tag":"BadRequest"}`). **Fallback candidate:** `GET /console/api/internal/orgs/{orgId}/go/status` is a **support-staff-only** variant and returns HTTP 403 `{"_tag":"Forbidden"}` for a regular account. Candidate routes (`CONSOLE_STATUS_ROUTES`, first entry is the verified one, `CONSOLE_STATUS_SUFFIX = "/go/status"`): `/console/api`, `/console/api/internal/orgs/{orgId}`, `/console/api/orgs/{orgId}`, `/console/api/v2/orgs/{orgId}`, `/console/api/v1/orgs/{orgId}` — `bin/opencode-usage` walks the identical list. Headers: `Cookie`, `Accept: application/json`, `x-org-id`, `Referer: https://opencode.ai/console/{orgId}/go`. curl runs with `-w 'HTTPSTATUS:%{http_code}'` and the marker is split off the LAST occurrence in stdout. Retry rules: **only HTTP 404 (route moved; empty body) advances to the next candidate route**; **HTTP 5xx is transient — the SAME route is retried in place (plasmoid up to 4 attempts, CLI up to 3), then reported as "Console API temporarily unavailable (HTTP 5xx) — retry shortly" (the endpoint is currently intermittent: most live requests answer 500 `{"_tag":"InternalServerError"}`)**; 401 (bad session), 403 (denied), 400 (missing/bad `x-org-id`) and network errors are final. When every candidate 404s, plasmoid and CLI surface a "Console API route not found — check for a widget update" message. The legacy workspace Go page is retired (302 only). Workspace/org ids look like `wrk_...` or `org_...`.
- **Response Handling:** `api.js` parses the console `go/status` JSON: `access` may be `null` (no Go subscription on the workspace), otherwise read `access.meters.fiveHour` / `week` / `month` (`limitMicroCents`/`usedMicroCents` are BigInts serialized as **strings** — accept string or number). Percentage matches the console exactly: `floor((used*200 + limit) / (limit*2))` clamped to 0..100, 0 when `limit <= 0`. Labels: `fiveHour` → Rolling (5h), `week` → Weekly, `month` → Monthly; the `month` meter has no `resetsAt` (it resets at `access.endsAt`). Status → message mapping: 401 `{"_tag":"Unauthorized"}` = dead session (final, no route retry), 403 `{"_tag":"Forbidden"}` = restricted/support-only route, 400 `{"_tag":"BadRequest"}` = missing or bad `x-org-id`, 5xx `{"_tag":"InternalServerError"}` = transient (retry), and 404 means the API route moved — **not** a bad session.
- **Authentication:** Session cookie is `__Host-console_session` (~39-char `st_...` token) in the `Cookie` header; legacy `auth=Fe26.2**` no longer authenticates. Server reads **cookies only** — no `Authorization` header. Paste handling (`buildCookieHeader`/`normalize_cookie`, `KNOWN_COOKIE_NAMES = __Host-console_session/console_session/auth`): values already carrying a known `name=` pass through untouched (incl. full Cookie headers); bare `Fe26...` → `auth=`; any other bare value → `__Host-console_session=` (even with `=`/base64 padding); surrounding DevTools quotes stripped. VALUE must be ≥16 chars. Copy fresh from opencode.ai/console → DevTools → Application → Cookies → opencode.ai → `__Host-console_session`.
- **Network Transport:** Qt's QML `XMLHttpRequest` **silently strips the `Cookie` header** (governed by `QNetworkRequest::CookieLoadControlAttribute`, regardless of `withCredentials`), so the plasmoid cannot authenticate via XHR. Instead, `UsageFetcher.qml` runs `curl` through Plasma's `executable` dataengine (`org.kde.plasma.plasma5support.DataSource`) and passes the captured stdout to `Api.parseCurlOutput`. The cookie value is shell-quoted (`shellQuote`) before inlining — never interpolate credentials into a shell string unescaped.
- **Error Handling:** Widget clears stale mock data on real errors without forcing Demo Mode. Transient 5xx (`isTransientError`) keeps the last known live figures on screen with a "showing last known figures" note instead of blanking the card; other errors surface clean messages.
- **Layout:** The widget uses horizontal-only layout (`layoutMode` hardcoded to `"horizontal"`). Tabbed and all-in-one views are disabled. Use `Plasmoid.configure()` (Plasma 6 API) — the old `plasmoid` id does not exist.
- **QML Binding Scope:** When passing properties to child components, always qualify with the parent's `id` (e.g., `fullRoot.usagePercent`) to avoid self-binding loops where the child resolves the unqualified name to its own property.
- **Branding & Assets:** Vector artwork uses the redesigned cyan-teal OpenCode Go logo SVG (`<O✦>` code brackets enclosing center ring and glowing spark) located in `assets/icon.svg` and `contents/icons/com.mayanktaker.opencodego-usage.svg`. `install.sh` generates PNG app icons across all system theme sizes (16px–128px) directly from this SVG.
- **Release Notes:** end-user changelog lives in `CHANGELOG.md` (see also `README.md` "What's New"); `AGENTS.md` stays concise and points here instead of duplicating it. `.agents/AGENTS.md` is a symlink to this file — never recreate it as a duplicate copy.

## GNOME Extension (`gnome-extension/`)
- **Scope:** GNOME Shell port of this plasmoid — panel icon + hover popup with Rolling/Weekly/Monthly usage. UUID `com.mayanktaker.opencodego-usage`, **GNOME Shell 46–50** (46+ only: the prefs loader contract changed, see below). Verified live on Manjaro / GNOME 50.4 / Wayland.
- **Files:** `extension.js` (indicator + async curl transport + refresh timer), `popup.js` (St rows: header, 3 bars, footer), `settings.js` (schema resolver + key names), `prefs.js` (libadwaita page), `api.js` (port of `contents/code/api.js`), `schemas/`, `install.sh`, `tests/`.
- **API parity:** `gnome-extension/api.js` is a port of `contents/code/api.js` — same routes, cookie rules, percentages, error mapping. When console API behavior changes, update **both** files.
- **GNOME 46+ contracts (both were live-test failures, both pinned by `tests/contract-test.js`):**
  1. **Schema resolution:** `new Gio.Settings({schema_id})` cannot see an extension's own `schemas/` dir. `settings.js` must build a `Gio.SettingsSchemaSource.new_from_directory(<ext>/schemas, default, false)` from `GLib.filename_from_uri(import.meta.url)`. In the shell you may also use `this.getSettings()` (requires `"settings-schema"` in `metadata.json`); do **not** mix the two styles.
  2. **prefs.js entry point:** the shell does `new prefsModule.default({...metadata, dir, path})` then `prefsObj.fillPreferencesWindow(this)`. So `prefs.js` default-exports a **plain class with a `fillPreferencesWindow(window)` method** — NOT an `Adw.PreferencesWindow` subclass. The shell owns the window (`ExtensionPrefsDialog extends Adw.PreferencesWindow`); a window subclass builds a second unreachable one and the visible dialog stays empty. `popupMenu.js` must be imported as `import * as PopupMenu` (it has **no default export**).
- **Popup rebuild gotcha:** `PopupMenuBase.removeAll()` only destroys children that are registered `PopupBaseMenuItem`s. Rows added straight to `menu.box` survive and duplicate the popup every refresh. Always `menu.removeAll()` **then** `menu.box.destroy_all_children()`.
- **Transport:** curl runs through `Gio.Subprocess` with `communicate_utf8_async` — never `GLib.spawn_command_line_sync`, which blocks the whole shell for up to `--max-time 15`. One request in flight (`_inFlight`); `cancelRequest()` force-exits and nulls the handle so a pending callback bails out on `disable()` or a settings change.
- **Settings:** gsettings `org.gnome.shell.extensions.opencodego-usage` — `workspace-id` (s), `auth-cookie` (s), `refresh-minutes` (u, default 5, min 1). From a shell, read/write with `GSETTINGS_SCHEMA_DIR=~/.local/share/gnome-shell/extensions/com.mayanktaker.opencodego-usage/schemas gsettings ...`; the schema is not on the default path.
- **Tests:** `bash gnome-extension/tests/run-tests.sh` (compiles the schema, then runs `api-test.js` + `contract-test.js` under `gjs -m`).
- **Install/test:** `bash gnome-extension/install.sh`. A running GNOME Shell **never** picks up a newly installed extension and offers no rescan, so the installer queues the UUID in dconf `enabled-extensions` when `gnome-extensions enable` fails — a first install still needs logout/login. After edits: reinstall, then check `journalctl --user -b | grep -i opencodego` and `gnome-extensions info com.mayanktaker.opencodego-usage` (`State: ACTIVE`).
- **Live-test rig (no logout needed):** a headless shell on a private session bus reproduces every runtime path — `dbus-daemon --session --print-address=3 --fork`, then `DBUS_SESSION_BUS_ADDRESS=<addr> gnome-shell --headless --virtual-monitor=1400x900`, then `gnome-extensions info/prefs` against that address. GNOME 50 dropped `--nested`; `--wayland` now means display-server only.
- **Open item:** panel icon uses the `applications-system-symbolic` fallback. GNOME Shell does not add an extension's `icons/` dir to the St icon theme, so the branded `icons/opencodego-symbolic.svg` will not resolve until the extension prepends a search path itself.

## Testing Changes (MANDATORY after any QML/UI edit)
Plasma caches compiled QML and the config dialog does **not** pick up edits to `contents/ui/*.qml` or `contents/config/*.qml` until caches are cleared and the shell restarts. After changing widget UI or config pages you MUST:
1. Upgrade the installed plasmoid from the repo: `bash install.sh` (runs `kpackagetool6 -t Plasma/Applet -u .`, purges all Plasma QML bytecode caches, rebuilds the sycoca index, and restarts plasmashell).
2. **Fully close the settings/config dialog** before reopening it — a config window left open across the restart keeps a stale in-memory tab list (this is the usual cause of "old tabs / duplicate tabs" after a layout change).
3. If changes still don't appear, manually purge caches and restart: `rm -rf ~/.cache/plasmashell ~/.cache/plasmawindowed ~/.cache/qmlcache ~/.cache/kcmshell6 ~/.cache/systemsettings ~/.cache/kwin` then restart plasmashell, and `killall kcmshell6 systemsettings` to kill any lingering config processes.
Note: the installed copy under `~/.local/share/plasma/plasmoids/com.mayanktaker.opencodego-usage/` is a **separate copy**, not a symlink — edits in the repo are only live after the upgrade step above.

### Quick Visual Smoke Test (before/after any UI change)
After `bash install.sh`, render the widget standalone and capture it for review:
```bash
nohup plasmawindowed com.mayanktaker.opencodego-usage >/tmp/opencode/pw.log 2>&1 &   # full representation in its own window
sleep 10
spectacle -f -b -n -o /tmp/opencode/pw_test.png   # capture screen (capture tools are display-dependent)
```
Check `/tmp/opencode/pw.log` is free of QML errors, then inspect the captured card: the header stripe must span full width edge-to-edge with top corners matching the card radius, and (if `showBorder` is enabled) a full 1px border including the top edge. On Wayland, `xdotool`/`qdbus` window lookups often return nothing — rely on the screenshot instead. Note: `plasmawindowed`'s own window geometry (see `~/.config/plasmawindowedrc`) can differ from the rendered card size, so it is NOT a valid way to verify applet sizing — applet popup width is fixed by `Layout.preferredWidth` in `FullRepresentation.qml`.
When done, kill only by exact PID to avoid `pkill -f plasmawindowed` matching the invoking shell's own command line (which contains the same string) and killing the shell mid-command:
```bash
kill $(ps -eo pid,args | grep '[p]lasmawindowed' | awk '{print $1}')
```
